## Implementation boundary

Keep delivery disabled until the implemented HTTPS adapter and configuration are reviewed. Preserve bodyless authenticated requests, persisted cooldown/hourly limits, a synchronous transaction-worker delivery seam, account lock and delivery-before-token-commit ordering. Keep blocking authority/transaction work off the event loop. Return fixed public errors, independent of provider exception text. Never automatically retry an uncertain send or claim exactly-once delivery.

The adapter uses stable locked HTTPX 0.28.1, fixed `https://api.resend.com/emails`, normal TLS verification, no redirects/proxy inheritance/retries, a three-second asynchronous send deadline, finite phase timeouts and a 16 KiB identity-encoded JSON response cap. It validates the recipient from the locked account against the enabled exact address and checks the canonical HTTPS origin. A definite HTTP 200 with a valid message identifier is required for acceptance. Its UUID-shaped identifier check is intentionally conservative. Each deliberate attempt has a random idempotency key; it does not deduplicate a separate later attempt. Plain text includes the secret only in the confirmation-link fragment, with no tracking metadata. Tests use mock transport, synthetic addresses and disposable local databases; real delivery remains unproven. [Resend send API](https://resend.com/docs/api-reference/emails/send-email), [HTTPX timeouts](https://www.python-httpx.org/advanced/timeouts/)
