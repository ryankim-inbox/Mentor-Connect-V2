## Proven product defect and fix

Room/DM socket admission and legacy DM message receipt performed synchronous authority/DB work on the single ASGI event loop. A delayed DB operation there prevented unrelated HTTP responses from progressing. REST handlers and room socket sends already used worker execution.

Six causal regressions gate authority or transaction entry for room admission, DM admission and DM receipt. An independent OS thread submits the actual health route to the same loop only after the gate has entered. The test requires a complete HTTP 200 response before releasing that DB wait. An external bounded watchdog prevents deadlock; no sleep or adjusted product timeout makes the test pass. All six failed at this exact assertion before the fix (18.35s), then passed after the fix.

The fix moves each complete admission check/transaction lifetime into the existing threadpool and routes legacy DM receipt through the canonical synchronous send helper in that pool. No connection/cursor crosses threads. Current ownership, room/DM membership and bilateral block checks remain. Socket acceptance, registries, async transport and broadcast stay on the loop. Commit still precedes broadcast; no BackgroundTasks argument creates a second broadcast. Worker count, request deadlines, REST idempotency and retry behavior are unchanged. This removes the proven blocking path; it neither adds finite DB operation bounds nor proves that path caused the historical 504.

The six regressions plus existing mission/broadcast units passed 44 tests in 0.39s. Real PostgreSQL/socket/role/idempotency regressions passed 38 tests in 24.19s. These overlap the final full suite and are not additional unique coverage.
